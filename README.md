# Basic [VK Bridge](https://github.com/VKCOM/vk-bridge) + [VKUI](https://github.com/VKCOM/VKUI) + [VK Miniapps Router](https://github.com/VKCOM/vk-mini-apps-router) app

Этот шаблон предоставляет базовый код и настройки для создания мини-приложения внутри ВКонтакте.  
В качестве сборщика проекта выступает [Vite](https://vite-docs-ru.vercel.app/guide/), подробнее про его конфигурацию и дополнительные плагины можно прочитать [здесь](https://vite-docs-ru.vercel.app/config/) и [здесь]().

## 🚀 Запуск мини приложения

Запустите ваш мини апп

```sh
 yarn start
```

Перейдите на [devportal](https://dev.vk.ru/ru) или в [управление](https://vk.ru/apps?act=manage) и создайте новый мини апп.  
Вставьте URL на котором работает ваше приложение в настройки, предварительно включив режим разработки.
Теперь можете открыть мини апп, нажав на его иконку.
Список всех созданных вами мини приложений вы сможете найти [тут](https://vk.ru/apps?act=manage) или [тут](https://dev.vk.ru/ru/admin/apps-list).

## 🌐 Деплой мини приложения

Для того чтобы поделиться приложением запущенным на localhost со своими друзьями, вы можете скачать утилиту vk-tunnel и запустить уже подготовленный скрипт из package.json

```sh
yarn global add @vkontakte/vk-tunnel
yarn run tunnel
```

После чего вы получите ссылку, по которой ваше приложение будет доступно с любого устройства, подробнее про vk-tunnel можно прочитать [тут](https://dev.vk.ru/ru/libraries/tunnel).

Для того чтобы захостить ваше приложение на сервера ВКонтакте нужно зайти в vk-hosting-config.json и указать id вашего приложения. Далее можно запустить уже подготовленный скрипт:

```sh
yarn run deploy
```

После чего, вы получите бессрочную ссылку на ваш мини апп.

## 🤖 Автодеплой с токеном (без повторного входа)

Деплой на хостинг VK требует ключ доступа (`access_token`). Два способа:

1. **Первый интерактивный запуск** — `npm run deploy` напечатает ссылку авторизации,
   попросит код подтверждения и сохранит токен в системное хранилище: дальше вход не потребуется.
2. **Токен в `.env`** — возьмите `access_token` в карточке приложения на
   [dev.vk.ru](https://dev.vk.ru/ru) (раздел «Ключи доступа») и положите в `.env` в корне проекта:

```sh
MINI_APPS_ACCESS_TOKEN=<ваш токен>
```

`deploy.cjs` сам подхватывает переменные из `.env` (реальные переменные окружения имеют приоритет),
файл указан в `.gitignore` и не коммитится; образец — `.env.example`.

После этого деплой идёт без повторной авторизации:

```sh
npm run deploy:dev   # только dev — обычно НЕ требует подтверждения телефона
npm run deploy:prod  # production — VK может запросить подтверждение
npm run deploy       # dev + production (оба окружения)
```

> 🚨 Если после `npm run deploy` навигация приложения в VK снова даёт 404 —
> почти наверняка обновилось только dev-окружение, а по ссылке `vk.com/app54647551`
> открывается **production**, где лежит старая сборка. Проверьте:
> 1. В консоли деплоя должен быть показан блок «URLs changed for production:».
> 2. На вопрос *«Would you like to update prod urls?»* ответьте **да**.
> 3. Подтвердите production-деплой: push в приложении VK на телефоне или код из
>    «Администрирования» приложения (см. ниже).

> ⚠️ Подтверждение production-деплоя (push в приложение VK на телефоне или код из
> «Администрирования» приложения) — это защита на стороне VK, токен её не отменяет.
> Если push-уведомление не приходит:
> 1. В приложении VK на телефоне должен быть авторизован аккаунт владельца/админа приложения.
> 2. Включите уведомления: Настройки телефона → VK, и внутри VK → Уведомления.
> 3. Либо подтвердите кодом: деплой сам запросит `Please, enter code from Administration:` —
>    введите код из «Администрирования» приложения прямо в консоль (переменной окружения
>    для кода в v1.0.2 нет).

### Переменные окружения (`.env`)

| Переменная | Значение | Описание |
| --- | --- | --- |
| `MINI_APPS_ACCESS_TOKEN` | токен | Ключ доступа для деплоя (берётся в настройках приложения на dev-портале) |
| `MINI_APPS_ENVIRONMENT` | `dev` / `production` / `both` | Какое окружение обновлять (`both` по умолчанию) |
| `MINI_APPS_APP_ID` | число | Переопределяет `app_id` из `vk-hosting-config.json` |

Это полный список: `vk-miniapps-deploy` v1.0.2 читает из окружения только эти три переменные.
Неинтерактивный режим и обновление URL задаются **полями** в `vk-hosting-config.json`:
`"noprompt": true` убирает все вопросы (тогда `update_prod` / `update_dev` берутся из того же файла,
сейчас `1` / `1`), а `"update_prod"` / `"update_dev"` управляют обновлением URL окружений.
Переменных `MINI_APPS_NOPROMPT`, `MINI_APPS_CONFIRM_CODE`, `MINI_APPS_UPDATE_PROD/DEV` в этой версии
нет — они молча игнорируются, и запуск деплоя без ответа на вопрос о подтверждении завершается
с кодом 0, ничего не выгрузив.
